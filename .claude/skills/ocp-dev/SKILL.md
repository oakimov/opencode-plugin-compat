# OCP local-dev skill

Drive host wiring only through `./scripts/ocp-dev.sh`. Do not resurrect deleted per-host shell scripts. Do not rewrite a host config file from parsed JSON.

## Hard rules

- Hosts are read-only. Never edit MiMo, Kilo, OpenCode, pi, omp, or deepseek-harness source, packages, or installed binaries.
- Consumer provider checkout is read-only in local mode. Never shim `cursor-opencode-provider/dist/index.js` in place.
- Config edits must be surgical. Never `JSON.stringify` a user's `kilo.jsonc` / `mimocode.json` / `opencode.json(c)` / `pi-bridge.json`. Comments, permissions, MCP, agents, and sibling plugins stay.
- Three families, three mechanisms. Do not run `ocp setup` against pi/omp/dsh. Do not put Pi/OMP/DSH ids into `packages/adapter`.
- Prefer the script over hand edits. If a config is already broken, diagnose first, then either `unshim` + `run` or a targeted surgical edit via `scripts/ocp-dev/jsonc.ts`.

## Commands

From the repo root:

```bash
./scripts/ocp-dev.sh run                      # local OCP + local provider, every installed host
./scripts/ocp-dev.sh run --mode npm           # published packages
./scripts/ocp-dev.sh run kilo mimo opencode   # named hosts only
./scripts/ocp-dev.sh unshim                   # remove OCP slot; keep the rest of config
./scripts/ocp-dev.sh unshim pi
```

`run` and `shim` are aliases. Default mode is `local`.

| Variable | Role |
|---|---|
| `OCP_DEV_PROVIDER_PATH` | provider checkout (else sibling, else `~/Projects/cursor-opencode-provider`) |
| `OCP_DEV_PLUGIN` | npm name (default `cursor-opencode-provider`) |
| `OCP_DEV_STATE_DIR` | wrapper/manifest root (default `~/.cache/ocp-dev`) |
| `OCP_DEV_BRIDGE_VERSION` / `OCP_DEV_PLUGIN_VERSION` | npm pins for pi-family |

Hosts: `opencode`, `mimo`, `kilo` (clone family), `pi`, `omp` (Pi family), and `dsh` (DSH family). Paths and CLIs: [references/hosts.md](references/hosts.md).

## Choose the action

| User wants | Do |
|---|---|
| Live against this OCP checkout | `./scripts/ocp-dev.sh run [hosts]` |
| Live against published packages | `./scripts/ocp-dev.sh run --mode npm [hosts]` |
| Back to no OCP slot | `./scripts/ocp-dev.sh unshim [hosts]` |
| "What state is this machine in?" | Diagnose below; do not guess |
| Config looks destroyed / comments gone | Diagnose, restore from backup if the user has one, then surgical re-insert. Do not stringify the file again. |
| Stock provider entry contains `generated by ocp setup` | `unshim` (repairs dirty stock). Do not hand-edit the checkout. |

Name hosts when the user names them. With no names, the script acts on every host found on PATH.

## Diagnose

Inspect, do not mutate. Report family, mode, and whether stock is dirty.

1. **Installed CLIs** — `command -v` for `opencode`, `mimo`, `kilo`, `pi`, `omp`; DSH is `pnpm --prefix <deepseek-harness> dsh`.
2. **Manifest** — `~/.cache/ocp-dev/<host>/state.json` (or `$OCP_DEV_STATE_DIR`). Missing means that host is not clone-wired by this tool.
3. **Config file** — first existing candidate from [references/hosts.md](references/hosts.md). Read it as text. Confirm `$schema`, `permission`, `mcp`, `agent`, and comments still exist.
4. **OCP slot**
   - Clone: `plugin` contains the wrapper path (`…/ocp-dev/<host>/provider/dist/index.js`) for local, or `cursor-opencode-provider@latest` for npm. `provider.cursor.npm` matches.
    - Pi family: `pi-bridge.json` `providers[].package` is an absolute `dist/index.js` (local) or the bare package name (npm).
    - DSH: `~/.dsh/profiles/web/cordis.patch.yml` `ocp-dsh-bridge` `config.providers[].package` is an absolute `dist/index.js` (local) or the bare package name (npm).
5. **Wrapper** — local clone mode: `dist/index.js` contains `generated by ocp setup` and `ocp-lm-runtime.js` exists. Stock checkout must **not** contain that marker.
6. **Stock provider** — `$OCP_DEV_PROVIDER_PATH` or sibling/`~/Projects/cursor-opencode-provider`. Dirty if `dist/index.js` has `generated by ocp setup` or `node_modules/@opencode-ai/plugin` is a symlink.
7. **Doctor** (clone only) — `bun packages/ocp/bin/ocp.ts doctor --host <mimo|kilo|opencode>`.
8. **Models** — `<host> models` (clone) or restart + model picker (pi/omp/dsh). Expect `cursor/*` or `cursor-opencode/*` when the provider is wired.

### State matrix

| State | Manifest | Config slot | Wrapper | Stock checkout | Pi packages |
|---|---|---|---|---|---|
| **local shim** | present, `mode: local` | wrapper `file://` or absolute wrapper path | instrumented | clean | local `pi-bridge` checkout installed |
| **npm shim** | present, `mode: npm` | `cursor-opencode-provider@latest` / bare name | absent | clean | published `@opencode-compat/pi-bridge` |
| **unshimmed** | absent | no wrapper path, no OCP-managed npm slot; user plugins remain | absent | clean | bridge/plugin uninstalled by script |
| **factory** | unshimmed **and** stock clean **and** no leftover `~/.cache/ocp-dev/<host>` | same as unshimmed | absent | clean, real `@opencode-ai/*` packages | same as unshimmed |
| **broken** | anything else: dirty stock, stringify-stripped jsonc, slot pointing at stock checkout, missing wrapper, comments gone | | | | |

Unshimmed is "OCP removed, user config kept". Factory is unshimmed plus a clean provider checkout. A missing `plugin` key on a user config that never had one is normal, not broken.

## Verify after a change

Re-read the same config file as text.

- **After `run` (local):** slot points at `~/.cache/ocp-dev/<host>/provider/dist/index.js`; user keys/comments intact; stock `dist/index.js` has no shim marker; wrapper `dist/index.js` has the marker.
- **After `run --mode npm`:** slot is the published package name; wrapper dir gone; user keys/comments intact.
- **After `unshim`:** OCP slot gone; previously evicted stock plugin paths restored if the manifest recorded them; `provider.cursor.npm` restored or removed only if we added it; `permission` / `mcp` / `$schema` unchanged; config file still exists unless this tool created an empty one.

If verification fails, do not keep stacking `run`. Diagnose, then fix.

## Fix

1. Dirty stock provider → `./scripts/ocp-dev.sh unshim` then re-`run` if the user still wants a shim.
2. Stale or half-applied slot, wrapper missing, npm/local mismatch → `unshim <host>` then `run <host>` (or `--mode npm`).
3. Slot points at the stock checkout → that is the dirty-stock failure mode. `unshim` (restores the path) then `run` so the slot moves to the wrapper.
4. User config lost comments or was rewritten wholesale → stop. Restore the user's backup if they have one. Then insert the slot with `run`, which uses surgical JSONC edits. Never pretty-print the whole file to "fix" it.
5. Pi/omp provider entry wrong, other providers intact → `run pi` / `run omp` (upsert) or `unshim` (remove only the Cursor/OCP entry). Do not `rm` `pi-bridge.json`.
6. Clone host models empty after a good-looking shim → re-run `bun packages/ocp/bin/ocp.ts setup --host <id> --mode file --dir <packages>` only if `run` already wrote the slot; otherwise just `run` again. Restart the host worker.
7. Need a one-off surgical edit → import `setPath` / `deletePath` from `scripts/ocp-dev/jsonc.ts`. Touch only the OCP-managed path. Re-parse and confirm sibling keys survived.

When reporting, name the files you read, the state you inferred, and the exact command you ran. Do not claim interactive host parity from unit tests alone.
